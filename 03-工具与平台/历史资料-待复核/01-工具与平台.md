# AI 视频工具与创作路线地图

> 本文不是工具排行榜，而是帮助创作者理解不同技术路线、选择工具并组合工作流的决策文档。平台功能、模型、价格、地区和授权可能变化；涉及具体能力时，应记录来源和核对日期。工具官网可访问，不代表当前账号能使用全部功能。

## 1. 先理解：AI 视频创作不是一张工具排名表

不同产品解决的是不同层面的问题：有的负责把创作流程尽量包办，有的专注生成单个镜头，有的提供多个模型入口，有的让用户搭建可复用的节点流程，有的负责改造已有视频，还有的提供本地运行或程序化调用能力。

因此，选型时先确定任务和控制需求，再选择工具；不要只根据热度、单次演示效果或价格做判断。

## 2. 七类创作路线

| 路线 | 主要解决的问题 | 适合的情况 | 主要代价或风险 | 重点验证 |
|---|---|---|---|---|
| 一站式包办平台 | 尽量在一个产品里完成创意、脚本、角色、分镜、生成、配音或剪辑 | 新手快速完成第一支作品；想先体验完整流程 | 某些环节可控性有限；导出和迁移可能受平台限制 | 是否真的覆盖端到端流程；角色一致性；导出规格；商用条款；积分总成本 |
| 专业视频生成器 | 生成、延展或修改具体视频镜头 | 对画面质量、运动、镜头表达或参考素材控制有明确要求 | 结果可能不稳定；多镜头叙事和角色连续性仍需额外管理 | 文生视频/图生视频；参考图或参考视频；时长、比例、镜头控制；失败是否扣费 |
| 多模型聚合平台 | 在一个界面中比较或调用多个模型 | 想快速横向比较模型，减少多平台切换 | 模型版本、参数、价格和开放时间可能与模型官方渠道不同 | 实际调用的模型版本；输入输出限制；积分换算；数据处理；是否支持导出与复现 |
| 节点式工作流 | 将素材处理、模型调用、控制参数和后处理连接成可保存流程 | 需要细粒度控制、重复运行、可追踪流程或复杂管线 | 学习成本高；节点、模型、插件和硬件依赖较多 | 工作流是否可导出；依赖清单；版本兼容；显存要求；运行失败定位能力 |
| AI 二创与编辑工具 | 对已有视频进行重绘、风格转换、局部修改、扩展、口型或特效处理 | 已有素材，希望修改而非从零生成 | 可能改变原片关键细节；处理边界和授权条件各不相同 | 哪些区域会变化；能否保留主体、动作和镜头结构；输入版权与输出授权 |
| 开源 / 本地工具 | 在本地或自托管环境运行模型、管理素材和工作流 | 希望增强控制、管理本地素材、降低对单一网页平台的依赖 | 需要硬件、环境配置、模型下载、维护和故障排查 | 显存和磁盘需求；模型许可证；安装步骤；更新成本；本地数据边界 |
| API / 自动化路线 | 用程序、任务队列或工作流批量调用模型和处理结果 | 人工流程已稳定，需要批量生成、归档、重试或接入 Agent | 开发和维护成本；调用费用；限流、失败和凭证安全问题 | 官方 API 是否开放；价格和速率限制；异步任务机制；重试策略；日志与数据条款 |

**分类说明：** 这七类不是互斥的。例如，一个聚合平台也可能包含 AI 二创能力；一个节点式流程可以调用云端 API；一站式平台生成的视频也可以进入专业后期软件。比较时应标注“主要定位”和“兼具能力”，不要强行只给工具贴一个标签。

## 3. 选型时先回答五个问题

1. **我要完成什么？** 第一支样片、剧情短片、动态漫、广告、已有视频改造，还是批量生产？
2. **我最在意什么？** 快速出片、画面表现、角色一致性、精细控制、低成本、隐私，还是自动化？
3. **我愿意投入多少？** 学习时间、订阅预算、单条成片成本、硬件和维护时间都要计算。
4. **我需要复现到什么程度？** 偶尔生成即可，还是需要记录模型版本、参数、素材和工作流，之后再次运行？
5. **结果要交付给谁？** 自己练习、公开发布、商业客户，还是由 Agent 后续读取和继续处理？这会影响版权、隐私、格式和可追溯要求。

### 快速决策建议

- **第一次做成片：** 先选一个容易使用且当前可访问的视频工具，加一个剪辑工具，完成短样片再评估。
- **角色和场景容易漂移：** 优先建立角色设定、参考图、场景资产和镜头连续性规则，不要只靠不断追加提示词。
- **需要比较模型：** 使用聚合平台或分别测试官方平台，但要统一输入、目标和评价标准，留意模型版本差异。
- **需要精细控制和重复运行：** 再研究节点式工作流；记录模型、节点、参数、素材与版本。
- **已有视频需要改造：** 先测试二创工具对原主体、动作和镜头结构的保留程度。
- **需要本地控制：** 评估硬件、安装和维护成本后，再选择开源本地方案。
- **需要批量或 Agent 调用：** 先证明人工工作流稳定，再使用官方 API 或明确支持的自动化接口；不要把模拟网页点击当作官方 API。

## 5. 不要只比较功能，要比较“完成一条成片的总成本”

工具成本至少包括：

- 订阅费、积分或按秒/按任务收费；
- 失败重试是否收费，以及为得到可用镜头需要尝试多少次；
- 人工整理角色、分镜、素材和后期的时间；
- 本地硬件、存储、电力、安装和维护成本；
- 导出、水印、商用授权、团队协作和 API 的额外限制。

建议使用同一任务做对照，而不是比较不同用户发布的零散演示。示例任务可以是：生成一个 8–10 秒镜头，人物外观固定，完成指定动作和镜头运动，输出目标比例，并记录成功次数、花费和后期修复时间。测试时长和规格应按工具实际支持情况调整。

## 6. 工具研究记录标准

每项信息都要标记证据来源，避免把营销介绍、社区反馈和个人实测混为一谈。

- **官方确认：** 官方文档或产品页面明确说明。
- **社区反馈：** 用户经验或第三方测评，需注明来源和日期。
- **个人实测：** 自己按记录步骤测试得到。
- **待验证：** 暂无可靠证据，不应写成确定结论。

每个工具至少记录：

- 定位：主要路线与兼具能力；
- 适用任务与不适用任务；
- 输入、输出、时长、比例、分辨率与声音能力；
- 参考图/视频、角色一致性、镜头与局部控制；
- 模型版本、参数、可复现程度与工作流导出能力；
- 成本、失败扣费、地区、排队和速率限制；
- 商用许可、素材权利、隐私与数据处理；
- 官方 API、批处理、Webhook 和自动化支持；
- 核对日期、来源链接、实测记录和未解决问题。

## 8. 面向 Agent / Skills 的工具描述要求

当这份知识库被 Code、DeepSeek Harness 或其他 Agent 读取时，工具介绍必须能支持下一步行动，而不仅是提供名称。

每个工具条目尽量明确：

1. **何时选它**：输入任务特征和选择条件。
2. **何时不要选它**：硬性限制、成本过高或能力不匹配的情况。
3. **需要什么输入**：文本、图片、视频、音频、参数、账号权限或本地依赖。
4. **会得到什么输出**：文件类型、任务 ID、视频地址、日志或工程文件。
5. **如何验证结果**：可观察的质量标准、失败条件和验收步骤。
6. **失败后怎么办**：重试、调整输入、换工具或交由人工处理。
7. **哪些操作必须人工确认**：付费任务、公开发布、删除素材、使用第三方肖像或商业资产。

不能只因工具有 API 就假定 Agent 可以直接使用。还需确认凭证配置、权限、输入输出格式、异步任务查询、错误处理、费用上限和人工审批机制。

## 9. 入门研究顺序

1. 先选一个当前可用的一站式平台或专业视频生成器，完成一支短样片。
2. 用相同任务测试第二个工具，记录质量、成本和修改时间，形成自己的对比。
3. 当角色、场景或镜头连续性成为瓶颈时，补充角色资产、分镜和一致性管理方法。
4. 当需要精细控制、复现或重复运行时，再研究节点式工作流和本地工具。
5. 当人工流程稳定且重复工作明显时，再接入 API、自动化和 Agent。

不要同时订阅大量工具。先用真实创作任务找到瓶颈，再针对瓶颈增加工具。

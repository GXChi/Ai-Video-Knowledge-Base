# AI 视频创作路线图与工具选型指南

> 用途：作为 MyDesk「AI 视频创作知识库」的路线总览与工具选型文档。工具功能、价格、模型开放情况会变化；购买或集成前应再次核对官方页面。
> 更新日期：2026-10-24

## 一、先建立完整的路线图

AI 视频工具不能简单放在一张表里排名，因为它们解决的是不同层次的问题：有些负责完整生产，有些负责生成单个镜头，有些负责组织工作流，还有些负责后期处理或 API 自动化。

### 路线 A：一站式 AI 短剧生产线

**关键词：省事优先、尽快出样片。**

代表候选：小云雀、纳米漫剧流水线、漫小芽、Seko、知漫剧等。

通常从小说或剧本开始，平台协助完成剧本解析、角色设定、分镜、视频生成、配音或项目编排。适合希望快速制作整集、暂时不想自己拼接所有环节的人。

重点验证：
- 输入剧本后，能自动完成哪些步骤，哪些仍需手工处理？
- 角色、服装、场景和画风能否跨镜头保持一致？
- 能否单独重做某个镜头，而不是整段返工？
- 导出分辨率、时长、水印、商用授权和积分消耗是什么？
- 项目能否保存、复用、导出素材或交给其他工具继续处理？

### 路线 B：专业视频生成器

**关键词：单镜头质量、镜头控制。**

代表候选：即梦、可灵、海螺、Vidu、Runway、Luma、Pika、PixVerse 等。

主要研究文生视频、图生视频、参考图、首尾帧、镜头运动、主体一致性和视频编辑。它们通常更适合逐镜头生成，再由创作者自己组织成片。

测试时不要只看宣传样片，应该使用同一组提示词、参考图和动作要求进行横向比较，并记录可用率和实际成本。

### 路线 C：多模型聚合平台与无限画布

**关键词：一个工作区管理多模型和创作素材。**

代表候选：LibTV、RooYun，以及 Krea、Higgsfield、OpenArt、Pollo AI 等提供多模型或创作画布能力的平台。具体模型和功能以各平台当前开放情况为准。

这类平台可能把剧本、角色图、提示词、视频、音频和生成步骤放在同一个工作区，部分产品支持画布或节点式编排。它们不一定自己训练底层模型，价值可能在于整合模型、管理素材和组织创作流程。

重点验证：实际接入哪些模型及版本；额度如何计算；画布步骤能否复用、导出或分享；素材和提示词能否关联；是否支持 API、Skills 或其他自动化接口。

### 路线 D：本地节点式工作流

**关键词：控制力、可复用、可调试。**

代表：ComfyUI + Wan 等开源模型；InvokeAI 更偏图像生成、编辑与视觉资产制作。

ComfyUI 通过节点连接模型加载、提示词、采样、图像处理、视频生成和输出等步骤。用户可以导入别人分享的工作流，也可以修改节点和参数。它适合研究生成过程、复用工作流和探索本地自动化，但需要承担模型下载、显存、环境配置、节点维护和运行时间成本。

开始安装前，先确认目标模型的显存要求、模型许可、硬盘空间和运行速度，不要为了省 API 费用而过早投入大量环境维护时间。

### 路线 E：AI 视频二创与视频改造

**关键词：基于已有视频修改内容或风格。**

候选工具包括 Runway 的视频编辑能力、部分可灵视频编辑能力，以及 ComfyUI 社区工作流等。可能的任务包括视频到视频、风格迁移、局部修改、延长镜头、背景处理、角色替换等。不同产品支持的修改范围差异很大，应按具体任务验证，不能仅凭“AI 视频编辑”这一标签判断能力。

### 路线 F：AI 自动剪辑与内容再利用

**关键词：已有素材的剪辑、切片与包装。**

代表候选：OpusClip、Vizard、Descript、剪映 / CapCut 等。这类工具常用于把长视频切成短视频、自动寻找高光、加字幕、调整画幅、编辑口播或整理旁白。它们与从零生成玄幻短剧的视频生成器不是同一类工具。

需要区分两种“二创”：
- **视频改造：** 把已有镜头变成另一种画风、修改人物或背景。
- **内容再利用：** 把长视频剪成多个短视频、添加字幕或重新包装。

### 路线 G：API + Python 自动化

**关键词：批量任务、程序控制、流程集成。**

候选方案：火山方舟 Seedance API、Runway API、fal.ai、Replicate、ComfyUI 本地 API，以及 n8n 等流程编排工具。

典型自动化流程：提交生成任务 → 查询任务状态 → 下载结果 → 检查失败并重试 → 保存视频和元数据 → 更新项目记录。

适合希望批量生产、持续迭代，或把视频生成整合到个人工具中的开发者。集成前必须核实官方 API、授权范围、计费方式、并发限制和数据处理条款。

### 七条路线如何组合

A、B、C 主要描述产品使用方式；D 描述工作流技术；E、F 描述视频处理任务；G 描述自动化接入方式。因此它们并非互斥的软件类别。例如，可以用 C 管理创作，用 B 生成镜头，用 F 完成剪辑，再通过 G 自动化重复步骤；也可以用 A 快速做出样片，之后再把最耗时的环节拆出来优化。

#### 正向提示词与负向提示词

**正向提示词（Positive Prompt）**：描述希望模型生成的内容，例如人物外貌、场景、动作、光线、镜头运动和艺术风格。

示例：

> 古装青年站在山巅，黑色长发随风飘动，云海翻涌，镜头缓慢推进，电影级光影。

**负向提示词（Negative Prompt）**：在支持该功能的模型中，描述希望尽量避免的内容，例如画面模糊、畸形手指、重复肢体、错误解剖结构等。

示例：

> blurry, distorted hands, extra limbs, duplicated objects, flickering

注意：不是每个视频模型都支持独立的负向提示词输入框；即使支持，也不能保证所有不希望出现的元素都被排除。实际写法应以所用模型的说明和工作流为准。

## 三、如何比较成本

不要只比较会员月费或单次生成价格。更有意义的是计算**最终可用视频的成本**。

| 路线 | 主要花费 | 容易忽略的成本 |
|---|---|---|
| 一站式短剧平台 | 月费、积分包 | 返工、导出限制、积分消耗 |
| 单模型视频平台 | 会员、生成积分 | 高质量模型或更长时长消耗更多额度 |
| 多模型聚合平台 | 统一订阅或点数 | 不同模型的额度消耗不一样 |
| ComfyUI 本地 | 显卡、电费、存储 | 部署、调参、等待和维护 |
| API 自动化 | 按生成量计费 | 失败重试、参考图生成、存储和任务调度 |
| AI 二创与剪辑 | 订阅、导出或处理额度 | 高分辨率处理、额外功能和人工检查 |

每次测试至少记录：
1. 生成了多少秒的视频。
2. 一共尝试了多少次。
3. 最后有多少秒可以实际使用。
4. 总花费是多少。
5. 花费了多少人工时间。
6. 导出是否带水印、是否满足目标分辨率和商用要求。

**可用成片成本 = 总费用 ÷ 最终可用视频秒数**

如果不同工具的画质和可用性差距很大，还应单独记录质量评价，不能只凭成本最低就判断最好。

## 四、教程研究方向

以下是优先学习的教程主题。链接和教程版本可能变化，打开后应确认内容与当前软件版本是否一致。

1. **ComfyUI + Wan 图生视频入门**：理解模型文件、节点连接、提示词、镜头运动、视频时长和输出。
2. **ComfyUI 基础工作流完整教程**：了解模型安装、节点依赖、工作流导入、参数修改和运行错误排查。不要把特定版本的模型参数直接套用到所有新模型。
3. **小云雀官方短剧工作流教程**：观察上传剧本、规划角色与场景、生成分镜、预演和重拍的流程，判断一站式平台自动完成了多少工作。
4. **LibTV 无限画布工作流入门**：观察文本、图片、视频和音频节点如何连接，以及如何组织可复用的创作步骤。
5. **ComfyUI 视频二创与角色替换**：作为进阶方向，了解参考角色、视频分析、人物区域处理和片段拆分，并核实教程使用的模型、节点和授权是否仍适用。
6. **视频生成 API + Python**：学习提交任务、查询状态、下载结果、失败重试和保存元数据。优先阅读官方开发者文档，再参考社区教程。

## 五、建议的研究顺序

考虑到你是程序员、对自动化有兴趣，但不希望一开始陷入过多工具和环境配置，建议分四步：

### 第一步：用一站式平台看清完整流程

先体验小云雀一类平台，尝试把一个短剧创意变成一段样片。重点记录剧本解析、角色资产、分镜、生成、配音、剪辑分别由谁完成。

**目标：** 了解完整生产线，发现最需要人工介入的环节。

### 第二步：选择一个专业生成器做对照测试

从即梦、可灵、海螺、Vidu 等中选一个作为主力，使用相同的提示词和参考素材测试效果。暂时不要同时购买多个会员。

**目标：** 找到画面效果、控制能力和成本都适合自己的生成工具。

### 第三步：体验画布或节点工作流

先看 LibTV 一类在线画布，理解素材与步骤如何组织；再通过教程了解 ComfyUI。确认电脑显卡、显存和模型需求后，再决定是否实际部署本地环境。

**目标：** 理解工作流的组织方式，建立可复用的创作流程。

### 第四步：最后再用 API 自动化

在确认模型效果和流程值得重复之后，再编写最小 Python 程序，实现任务提交、状态查询、视频下载、失败重试和元数据记录。

**目标：** 自动化稳定、重复的步骤，而不是把尚未验证的创作流程过早写进代码。

## 六、试用时的统一评估表

每个工具都使用同一组问题记录，避免只凭宣传片或一次成功案例判断。

| 评估项 | 记录内容 |
|---|---|
| 工具定位 | 一站式、生成器、聚合平台、节点工作流、二创、剪辑或 API |
| 实测任务 | 用同一份剧本、提示词或参考图完成什么任务 |
| 画面质量 | 人物、动作、镜头、光影、细节是否达到要求 |
| 一致性 | 跨镜头角色、服装、场景和画风是否稳定 |
| 可控性 | 是否能只重做某个步骤或镜头 |
| 可复用性 | 能否保存项目、模板、节点工作流和提示词 |
| 成本 | 总花费、生成次数、最终可用时长 |
| 速度 | 排队时间、生成时间、失败重试时间 |
| 导出 | 分辨率、时长、水印、格式和限制 |
| 权限 | 商用许可、输入素材权利、数据保留规则 |
| 自动化 | 是否有官方 API、SDK、MCP 或其他授权接口 |
| 结论 | 适合什么任务；当前仍有哪些待验证问题 |

## 七、研究与记录规范

对工具资料应明确区分证据等级，避免把宣传内容写成已验证事实：

- **官方确认：** 来自官方文档、产品页面、定价页或开发者文档。
- **社区反馈：** 来自用户实测、讨论或第三方评测，可能存在版本差异。
- **个人实测：** 自己实际操作并记录的结果。
- **待验证：** 暂时没有可靠证据，不能直接据此购买或开发集成。

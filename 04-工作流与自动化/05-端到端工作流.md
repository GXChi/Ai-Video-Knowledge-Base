# 端到端工作流

> 本文先给出可执行的流程骨架。具体按钮、参数和 API
> 以所选平台当前文档为准。第一次不要同时学习太多工具。

## 工作流 A：从零完成第一支 15--30 秒样片

### 目标

完成一个有开头、发展和结尾的短片；不追求一次达到商业成片质量。优先学会整个链路。

### 步骤

1.  **确定创意**
    -   选择一个原创、场景少、角色少的故事。
    -   控制在 3--6 个镜头。
    -   每个镜头只安排一个主要动作。
2.  **写出短剧本**
    -   用一句话说明主角目标和冲突。
    -   写出开头钩子、事件变化和结尾。
    -   删掉无法通过画面、对白、旁白或声音表达的信息。
3.  **锁定视觉方向**
    -   选择写实、动漫、3D 或其他明确风格。
    -   确定画面比例、主色调、光线和镜头质感。
4.  **制作角色和场景参考图**
    -   先做主角参考图。
    -   再做主要场景概念图。
    -   如果角色一致性不稳定，减少角色数量和镜头变化。
5.  **制作分镜**
    -   每个镜头写清时长、景别、动作、运镜和声音。
    -   标出高风险镜头，并先做低成本测试。
6.  **生成视频片段**
    -   先生成最关键的镜头，确认视觉方向。
    -   每次调整一到两个因素。
    -   不满意时先判断问题来自提示词、参考图、镜头复杂度还是模型能力。
7.  **剪辑合成**
    -   先按故事顺序拼接。
    -   调整节奏，再加入对白、旁白、音效、音乐和字幕。
    -   统一画面色调与响度。
8.  **验收和复盘**
    -   从头到尾看一遍，不只逐帧看。
    -   检查故事是否看得懂、动作是否连贯、字幕和声音是否准确。
    -   保存最终成片、提示词、素材和失败记录。

### 第一支样片的验收标准

-   [ ] 有明确的开头和结尾。
-   [ ] 镜头顺序能表达故事。
-   [ ] 主要人物在关键镜头中可识别。
-   [ ] 没有严重到破坏观看的连续性错误。
-   [ ] 声音、字幕和比例符合发布要求。
-   [ ] 保存了模型、提示词和素材记录。

## 工作流 B：电影感短片

1.  故事分析：找出视觉核心、情绪曲线和关键转折。
2.  美术设定：确定色彩、材质、光线和构图风格。
3.  角色 / 场景资产：建立参考图和连续性约束。
4.  镜头设计：逐镜头定义动作、机位、景别和运镜。
5.  关键帧测试：先确定构图和人物位置。
6.  视频生成：每个镜头独立生成，优先保证动作可控。
7.  选择与返工：比较多个候选片段，记录取舍原因。
8.  后期合成：用剪辑、声音和色彩统一不同生成结果。
9.  质量复核：检查节奏、连续性、授权与发布规格。

## 工作流 C：小说 / 剧本转成短片

``` text
原文 / 原创想法
    ↓
故事分析与改编边界
    ↓
短片梗概 + 情绪曲线
    ↓
角色 / 场景 / 道具清单
    ↓
分镜表
    ↓
镜头提示词与参考素材
    ↓
视频片段生成
    ↓
筛选、重生成与局部修正
    ↓
剪辑、声音、字幕、封面
    ↓
成片验收与发布
    ↓
复盘：沉淀提示词、资产、失败案例和工作流版本
```

## 工作流 D：逐步自动化

不要一开始就让 Agent 自动做所有事。建议按以下阶段推进：

### 阶段 1：人工执行，结构化记录

-   手工选择工具、输入提示词、下载结果。
-   保存每一步输入输出和文件名。
-   明确人工判断点。

### 阶段 2：半自动

-   让大模型生成结构化剧本和分镜 JSON。
-   自动创建目录、命名文件、生成任务清单。
-   仍由人确认角色设定、提示词和关键镜头。

### 阶段 3：API / 节点工作流

-   对有官方 API 的平台使用 API。
-   对本地节点工作流保存工作流文件与依赖版本。
-   加入任务状态、日志、失败重试和成本上限。

### 阶段 4：Agent / Skill

-   把稳定的单项任务封装为
    Skill，例如"剧本转分镜""提示词检查""生成结果复盘"。
-   为每个 Skill 明确输入、输出、工具权限、失败条件和验收规则。
-   对付费生成、公开发布、删除文件等操作保留明确的人工确认点。

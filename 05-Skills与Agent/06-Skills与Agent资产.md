# Skills 与 Agent 资产

> 目标：将知识库中的稳定经验转化为 AI
> 能够按步骤执行、检查和复用的任务资产。具体 Skill
> 文件格式应适配最终使用的 Agent /
> Harness，不要先假定所有系统使用相同格式。

## 1. 什么适合做成 Skill

适合： - 输入清晰、输出可检查的重复任务； -
有稳定步骤和明确质量标准的任务； -
需要反复使用同一套专业提示词的任务； - 能拆分成较小、可测试动作的任务。

暂时不适合： - 目标极其模糊、每次都需要大量人工判断的任务； -
依赖未授权网页操作或不稳定模拟点击的流程； -
尚未手工跑通、失败原因还不清楚的复杂流水线。

## 2. 可逐步建立的 Skill 清单

  ----------------------------------------------------------------------------------------
  Skill 名称        输入                     输出                     验收重点
  ----------------- ------------------------ ------------------------ --------------------
  故事创意分析      创意 / 原文              一句话梗概、冲突、风险   不擅自改变核心设定

  小说短片化        授权原文 / 原创故事      短片梗概与改编建议       标明新增情节与删减

  角色设定生成      故事、角色描述           角色设定卡和图像提示词   外貌锚点明确

  场景设定生成      故事、地点描述           场景卡和概念图提示词     空间关系清晰

  分镜生成          梗概、时长、风格         结构化镜头表             每镜头一个主要动作

  镜头提示词编写    镜头表、角色资产         单镜头提示词             镜头语言与动作一致

  提示词审查        提示词、模型能力资料     冲突、缺项和改进建议     不编造模型功能

  工具选型          任务、预算、约束         候选工具和理由           引用最新官方资料

  生成结果复盘      提示词、参数、结果描述   失败分类与下一步         一次只提出少量改动

  工作流文档生成    已验证步骤               可复用工作流说明         输入输出和回退明确
  ----------------------------------------------------------------------------------------

## 3. Skill 文档建议结构

``` markdown
# Skill：分镜生成

## 目的
将短片故事转为适合 AI 视频制作的镜头表。

## 适用条件
- 已有故事梗概。
- 已知作品形态、目标时长和画面比例。

## 不适用条件
- 用户要求先创作完整长篇小说。
- 故事关键信息缺失且不能合理假设。

## 输入
- story
- duration
- format
- style
- available_tools（可选）

## 执行步骤
1. 分析故事冲突与情绪变化。
2. 确认关键事件和不能改变的设定。
3. 拆分镜头，每镜头一个主要动作。
4. 检查总时长和空间连续性。
5. 标注高风险镜头与替代方案。

## 输出
- 镜头表
- 角色 / 场景 / 道具清单
- 高风险镜头列表
- 待确认问题

## 质量检查
- 不虚构关键情节。
- 每个镜头都有动作、景别和时长。
- 说明模型能力不确定的部分。
- 输出可供后续任务直接使用。

## 失败处理
若信息不足，列出最关键的缺失信息；若只是次要细节缺失，先明确假设并继续。
```

## 4. 让 AI 能读懂知识库的原则

-   每个文件有清楚标题、用途和适用范围。
-   关键资产有稳定 ID 和版本号。
-   工具能力与价格尽量链接到官方文档，不把过期数字写死在多个文件里。
-   把"原理说明"和"可直接执行的提示词"分开。
-   把"待验证"和"已验证"标明。
-   工作流说明输入、输出、依赖、步骤、错误处理和验收标准。
-   不把密钥、访问令牌、私人素材或未授权内容写进知识库。
-   对 Agent 使用外部工具设置成本限制和权限边界。

## 5. 给未来 Agent 的总规则草案

``` text
你正在使用“AI 视频创作知识库”。执行任务时必须优先检索已有知识资产，而不是直接从零生成。

规则：
1. 先判断任务类型：创意、剧本、角色/场景、分镜、提示词、视频生成、后期或自动化。
2. 查找与任务匹配的工具卡片、提示词、工作流和 Skill。
3. 区分已验证经验、待验证建议和外部资料；不能把待验证内容描述成已验证结论。
4. 如果工具能力、价格、API 或平台规则可能变化，优先查看官方最新文档。
5. 复用资产时，保留适用条件、版本、限制和来源；不机械照搬不匹配的模板。
6. 重要信息缺失时，优先提出一个最关键的问题；非关键细节可先明确假设。
7. 对高成本生成先提供测试方案；设置生成次数或预算上限。
8. 不上传未获授权的素材，不暴露 API 密钥，不自动执行高风险或不可逆操作。
9. 完成后按验收标准检查输出。
10. 如果本次验证出新的有效经验，输出一份“建议更新的知识资产”，但未经确认不要覆盖原始资产。
```

## 6. 版本管理建议

-   `draft`：刚建立的草案。
-   `testing`：正在测试。
-   `verified`：在记录的条件下验证成功。
-   `reusable`：有清晰输入输出、限制和复现步骤，可供重复使用。
-   `deprecated`：工具、模型或流程变化后不再推荐。

版本号可以采用
`0.1.0`、`0.2.0`、`1.0.0`。提示词结构有明显变化时更新版本，并保留旧版的实验记录。

# 整体架构与使用说明

状态：已按确认的调整方向更新，内容仍持续完善  
版本：0.2  
更新：2026-11-16

## 一、知识库的用途

知识库保存可复用的概念、方法、教程、案例和模板，供人阅读，也供 AI 在具体任务中检索参考。具体作品的剧本、素材与工程另行保存，知识库可引用其分析结果，不混存整个项目。

知识库首先需要让读者理解：这个领域是什么、常见概念怎样关联、实际能做什么，再逐步深入专题。它不是只列术语的提纲，也不通过文章数量显示学习进度。

## 二、内容层级与阅读关系

| 层级 | 作用 | 故事领域中的示例 |
|---|---|---|
| 领域 | 定义一组相关知识的范围 | 故事创作 |
| 主题 | 把相互关联的知识组织起来 | 人物与关系、情节与冲突 |
| 文章 | 解释一个可独立查阅的主题 | 故事是什么、故事的分类与表现形式 |
| 案例与练习 | 完整呈现、分析或验证所学内容 | 原创故事及分析、个人改写练习 |

这些层级不必都对应文件夹。一个主题只有一篇文章时可以直接成文；内容积累后再拆目录。

地图给出整体位置与链接，正文讲清概念与用法，案例提供足够完整的阅读对象。目录分类不是必须按顺序通过的学习关卡。

这是本库的组织方案，不是唯一的学科划分。故事创作可以独立服务口述、小说、漫画等方向；放在本库创作基础区，不意味着只能用于影视。

辅助目录为工具与平台、工作流与自动化、Skills 与 Agent、教程与案例、练习与项目记录、原始资料与归档。它们的实际名称与边界见[目录结构说明](01-建议目录结构.md)，不再使用与磁盘不符的辅助领域编号。

## 四、领域之间怎样联系

一种常见的影视创作路径是：

想法与材料 → 故事发展 → 场景与剧本 → 导演和视觉构思 → 分镜与资产准备 → 素材生成或拍摄 → 剪辑与声音 → 复盘。

它不是所有创作必须遵守的单向流水线。故事、人物和结构会互相发展；导演构思与美术也可能提前影响故事。不需要完成长篇定位表或系列总纲，才能尝试一个独立故事。

知识之间可以通过链接关联。一个概念有主要解释位置，其他领域说明其在当前任务中的作用，避免反复维护同一套定义。

## 五、阅读、讨论与更新

1. 用户确定想了解的主题。
2. 查阅现有资料与必要来源，直接编写可独立阅读的 Markdown 草稿；需要时附完整案例。
3. 聊天简要提供链接、阅读顺序与待核实内容。
4. 用户通过文字或语音反馈。
5. 根据问题局部修订，按需要再安排例子、对照或练习。
6. 分别记录文档状态、用户反馈、理解与实践情况。

知识点之间可以关联讲解；不每说一个术语就要求答题。新文档可以先于掌握确认保存，但不能因此默认用户已经理解。进入新的学习阶段由用户决定。

## 六、内容与来源状态

理论知识、特定作者的方法、工具经验和个人实验分别说明。方法注明作者与版本；工具信息注明核对日期；自编案例标明教学原创与反馈状态。不能把来源中的绝对化宣传直接变成通用定律。

AI 使用知识库时也要先读取相关内容，结合任务判断，不保证仅因文件存在就会自动检索、正确使用或生成优秀作品。

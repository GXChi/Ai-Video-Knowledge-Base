# 知识库架构与阅读方式调整方案

状态：用户已于 2026-11-16 确认调整方向；目录、管理规则与首组故事材料已落实，其他专题按阅读需要补充。
编写日期：2026-11-16
用途：明确知识库如何组织、如何阅读，以及现有文件需要怎样调整。

## 1. 调整结论

现有知识库的一级分类可以继续使用，但「故事与编剧」的内部边界、知识地图、学习方式和旧文件编号需要调整。当前知识地图有可用的主题清单，但不足以直接作为入门教材或固定授课顺序。

知识库应同时服务两种用途：

- 人阅读：先有整体介绍，术语解释清楚，再逐步深入；正文和完整案例可以离开聊天记录独立阅读。
- AI 参考：能找到概念、方法、适用条件、案例和来源，区分通用知识、特定作者的方法、未验证建议和项目事实。

目录分类不等于强制学习顺序。阅读一篇完整介绍可以涉及多个相互关联的概念，不必逐个术语确认后才继续。

保留一级目录，在「01-影视创作基础」内部拆开故事创作与编剧，并把导演与镜头语言放进同一领域下组织：

```text
01-影视创作基础/
├── 01-故事创作/
├── 02-编剧与剧本写作/
├── 03-导演与镜头语言/
├── 04-摄影与画面设计/
├── 05-美术与视觉设计/
├── 06-分镜设计/
└── 07-剪辑与声音设计/
```

这是适合本知识库的导航安排，不是唯一的学科划分。

| 领域 | 主要问题 | 分类边界 |
|---|---|---|
| 故事创作 | 人物经历什么，事件如何发展，为什么值得关注 | 保存可用于口述、小说、漫画、影视等形式的通用知识；不要求先掌握剧本写作 |
| 编剧与剧本写作 | 怎样把故事组织成可表演、可制作的场景、动作和对白 | 保存剧本表达、场景组织、格式与改编等内容；引用故事基础，不重复解释整套故事知识 |
| 导演与镜头语言 | 观众看见、听见什么，人物怎样表演，镜头怎样表达 | 导演统筹视听表达，镜头语言是其中的重要工具；合在同一目录内，正文仍区分各自范围 |
| 摄影与画面设计 | 构图、光线、色彩、焦段和画面质感怎样组织 | 与导演和镜头知识互相引用，保留其独立的画面设计内容 |
| 美术与视觉设计 | 人物、服装、道具、场景和视觉风格怎样建立 | 侧重设计本身；生成手段归入 AI 视频生成 |
| 分镜设计 | 怎样把场景落实为可执行的镜头方案 | 综合前面知识，不把分镜表格式等同于镜头设计能力 |
| 剪辑与声音设计 | 怎样用素材、时间和声音形成作品 | 现阶段放在同一领域；有足够内容时才考虑细分 |

「02-AI视频生成」中的「提示词与分镜」后续建议改为「提示词与生成控制」，使模型实现方法与创作基础中的分镜设计边界更清楚。旧版混合文档先保留，核对后通过章节引用或专题文章逐步整理。

不新增单独的「小说写作」领域。当前先认识小说这种表达形式；如果后续确实系统学习小说，再讨论是否建立独立分支。

## 3. 故事创作的具体知识结构

下面是建议的内容位置，不是本次批量新建清单。只有实际有内容可写时才建立相应目录和文件。

```text
01-故事创作/
├── 00-故事创作知识地图.md
├── 01-故事基础/
│   ├── 01-故事是什么.md
│   ├── 02-故事的分类与表现形式.md
│   └── 03-故事从想法到成稿.md
├── 02-创意与主题/
├── 03-人物与关系/
├── 04-情节与冲突/
├── 05-结构与创作方法/
│   ├── 00-结构与创作方法导览.md
│   ├── 三幕式.md
│   ├── 故事圈-Dan-Harmon八步法.md
│   ├── 救猫咪-十五个节拍.md
│   └── 英雄之旅.md
├── 06-叙事与信息安排/
├── 07-故事发展与修改/
├── 案例/
└── 参考资料/
```

各部分的职责：

| 部分 | 核心内容 |
|---|---|
| 故事基础 | 故事的含义与范围；从简单经历到长篇故事；故事与片段、梗概、情节、叙事的初步关系；小说与剧本等表达方向的概览 |
| 创意与主题 | 灵感、故事前提、设定、吸引力、主题与表达意图；故事为何值得发展 |
| 人物与关系 | 身份与处境、目标与需求、性格与行动、人物关系、变化；如何让读者认识和关心人物 |
| 情节与冲突 | 事件、行动与后果、目标与阻碍、选择与代价、挫折与升级、悬念、伏笔、转折和结局；这些内容在此有主要归属 |
| 结构与创作方法 | 整篇事件如何安排；三幕式、故事圈、救猫咪、英雄之旅等有出处的方法；说明彼此联系、适用条件和局限 |
| 叙事与信息安排 | 视角、顺序、信息透露与隐藏；同一故事怎样讲会有不同体验；先解释基本概念再比较差异 |
| 故事发展与修改 | 从创意到梗概、大纲、故事稿；单篇与系列的不同组织方式；怎样诊断和修改具体问题 |
| 案例 | 可完整阅读的原创示例及其分析，或有明确来源的作品分析；理论正文链接到对应案例 |
| 参考资料 | 外部材料、历史整理和待复核内容，明确来源与状态 |

悬念、伏笔与反转在「情节与冲突」中有主要解释，在「叙事与信息安排」中讨论如何通过信息控制实现，并用链接关联。避免在两处重复维护相同定义。

## 4. 当前知识地图要改什么

原地图已重组为：[故事创作知识地图](../01-影视创作基础/01-故事创作/00-故事创作知识地图.md)。以下保留调整理由与拟定范围，实际状态以当前地图和目录说明为准。

### 4.1 学习目标改为故事创作自身的目标

建议替换为：

1. 理解故事的基本含义、范围与常见表现形式，知道故事可以从短小经历发展到长篇与系列。
2. 认识人物、事件、情节、结构、叙事等基本概念及其关系；先分别介绍，再比较。
3. 理解故事分类的不同维度，能说明正在阅读或创作的故事大致属于什么类型与组织形式。
4. 从一个想法发展出有具体人物、连贯事件和明确收尾的故事。
5. 学会设计人物行动、阻碍、后果、选择与变化，并判断故事的吸引力。
6. 认识常用结构与创作方法，知道它们帮助解决什么问题，不把某套方法视为所有故事的唯一标准。
7. 能针对人物、情节、结构和表达中的具体问题修改故事。

本领域的基本产出是一份完整、可阅读的故事稿及必要的构思材料。写成影视剧本属于后续方向，不作为本领域必须完成的学习目标。

### 4.2 调整现有主题

- 把「故事、情节与叙事的区别」从入门第一项，改为先介绍故事，再逐步认识情节与叙事，并解释它们如何关联。
- 补上分类、篇幅、表达形式、单篇与系列、从想法到成稿的介绍。
- 将人物与关系提前成为主要创作主题之一；它与情节互相发展，不规定必须写完人物档案才能想事件。
- 将情节设计独立成明确主题，关联冲突、悬念、转折、因果和结局。
- 将原来的「故事结构」扩展为「结构与创作方法」，加入有来源的具体方法导览。
- 将通用的场景目标、行动与变化放在情节知识中；影视场景写法和剧本对白放入编剧领域，必要时互相引用。
- 将剧本格式、剧本动作描写、影视剧本写作等转入编剧领域；故事梗概、大纲与故事修改留在故事创作领域。

基础介绍可以用几句话说明小说、剧本与故事的关系，并链接后续文档。这是帮助定位，不代表阅读故事基础前必须学会小说或剧本写作。

## 5. 分类与方法必须分开介绍

例如「成长、单元故事、动画、故事圈」并不是同一层级的四个类别：

| 信息 | 说明什么 | 示例 |
|---|---|---|
| 类型与内容体验 | 主要关注什么、带来怎样的体验 | 喜剧、爱情、悬疑、冒险 |
| 篇幅与容量 | 大致展开多少人物和事件 | 短篇、长篇；具体边界依表达形式而异 |
| 组织方式 | 单个故事与其他故事怎样连接 | 独立故事、单元故事、连续故事 |
| 表达形式 | 用什么形式呈现 | 口述、小说、漫画、影视剧本、动画作品 |
| 创作方法 | 怎样帮助构思、组织和检查内容 | 三幕式、故事圈、十五节拍等 |

读者应能查到陌生词的解释，而不是在方法介绍里突然遇到「单元制」「节拍」「中点」等词却找不到说明。

用编程语言和架构作类比，可以帮助理解「类型」和「方法」属于不同问题。但故事并非必须选定一种方法才可以写；同一作品可以用多种框架分析，仅凭成品符合某框架，也不能断言作者当时采用了它。

不使用「六套最主流」「所有故事都适用」等缺乏明确依据的排名或保证。

## 6. 创作方法怎样单独成文

故事圈、救猫咪等方法有足够的来源、步骤、应用与案例，可以分别成文；现阶段每种方法一篇文章就够了。需要多篇教程、案例或模板时，再为单个方法建立子目录。

每篇至少讲清：

1. 方法是什么，由谁提出，参考哪个版本。
2. 帮助解决什么问题，适用范围是作者主张还是本库的使用建议。
3. 基本步骤及术语解释。
4. 一篇完整案例，以及方法如何用于这个案例。
5. 可选的填写模板或检查方式。
6. 使用限制、常见误解与原始来源。

已找到的参考入口：

- [Dan Harmon 的八步原始教程存档](https://channel101.fandom.com/wiki/Story_Structure_101:_Super_Basic_Shit)：原始八步与后来的教程扩展应分开标明。
- [Save the Cat 官方十五节拍入门](https://savethecat.com/get-started)：影视剧本与小说的版本、位置建议需要分别核对，不能随意混用。
- [Christopher Vogler《The Writer's Journey》的十二阶段介绍材料](https://www.mccc.edu/~voorhees/dma135/Vogler_Practical_Guide.pdf)：英雄之旅需注明采用的作者与版本。

上述入口用于后续撰写，不表示本次已经写完或全面审查了这些方法的教程。

## 7. 正文与案例怎样组织

### 7.1 基础文档必须能独立读懂

以「故事是什么」为例，正文应包含：

- 对故事的基本介绍和用途，而不是只给一句定义。
- 故事的范围，解释为什么短小经历与长篇作品都可以讲故事。
- 故事内容与梗概、故事稿、小说、剧本之间的关系。
- 基本构成如何共同起作用，避免只列术语。
- 一个完整案例的链接和必要分析。
- 后续阅读入口，例如分类、人物、情节和结构。

不强制套满十一节模板，也不必每篇都加入 AI 工具操作。通用故事知识可以先讲清故事本身。

### 7.2 案例先完整呈现，再分析

一个独立案例文件可以这样安排：

```text
案例标题
来源与状态：原创示例／引用分析；是否经过读者反馈
用途：说明哪些概念，面向什么阅读层次

第一部分：完整故事正文
第二部分：人物与事件分析
第三部分：相关方法如何用于分析或构思（确有使用时说明）
关联知识与来源
```

故事正文应让读者先认识人物和处境，跟随行动及后果，读到一个能够理解的收尾。不能把几行梗概标成已经展开完成的故事作品。

短小的术语例句可以直接放正文，无须每个例句单建文件。需要反复引用或有足够篇幅的完整故事，再独立保存。

现有布熊、杯子示例可以作为局部说明，但不适合作为唯一的贯穿案例。后续优先选择接近用户阅读和观看经验、人物具体、事件有发展空间的案例。

### 7.3 例子不等于已经认可的作品

新写的示例标明为教学原创或草稿；项目已有故事则保留原有状态，不能因为用来分析就擅自改写。案例是否好看、方法是否适用，要给出具体分析，不能因为符合模板就保证效果。

## 8. 阅读与讨论方式的调整

建议将「先在聊天中逐点讲解，确认后才整理」调整为：

1. 用户提出希望了解的主题。
2. 检查现有文档、相关概念和可靠来源，确定本次写作范围。
3. 直接编写一篇有完整脉络的 Markdown 草稿，必要时附独立案例；不批量填满整个知识库。
4. 聊天里简要说明文档位置、阅读顺序和待核实事项。
5. 用户阅读后提出问题、评价或修改要求。
6. 根据讨论修改相应段落；需要时再做练习或深入阅读。
7. 文档写成、读者认可和学习掌握分别记录，不相互替代。

一篇有用的完整文档可以先于学习确认保存。学习确认决定掌握状态和后续节奏，不作为写草稿的前置条件。已有作品的修改与媒体生产授权另行按任务范围判断。

不默认用户已经掌握，也不把每次聊天末尾的测验设为必经步骤。

## 9. 文件与目录的拆分标准

- 文件夹用于容纳一组确实存在的相关文档，而不是给每个术语占一个位置。
- 一篇文章能讲清、且有完整用途的主题，可以单独成文；短术语说明放在相关正文中。
- 「分类」先写成一篇有实际内容的文章，积累了需要独立深入的类别后再拆目录。
- 地图只负责总览、位置和链接；主题文章负责解释；案例负责完整呈现与分析；三者不重复复制正文。
- 目前不预建空白的多层树，也不根据预期页数硬拆文章。

当前「01-故事与编剧/参考资料/02-剧本与创意.md」中的 `02` 是旧版平铺编号的遗留，并非这个文件是当前故事领域的第二课。目录序号和文件序号可以各自局部排序，但旧编号在这里确实容易误导。

后续命名时：`00` 用作本层入口或地图，编号只在同级有意义。参考资料可以用清楚的题名与状态，不必保留无意义的旧课程序号；重命名时同步引用。

## 10. 支持后续 AI 使用的最低要求

知识库内容更多，并不自动使 AI 创作更好。比单纯数量更重要的是：

- 标题与主题范围明确，有稳定可用的导航和关联链接。
- 能找到术语解释，能区分类型、方法和输出文稿形式。
- 方法标注来源与版本，案例标注来源及状态。
- 原理、作者建议和个人实测分清；不把营销用语写成通用定律。
- 通用知识与具体项目事实分开；选择方法时结合项目，而不是强行套用所有框架。
- 修改后核对引用，避免多个互相矛盾的定义和重复维护的模板。

仅把文档放进目录，不保证任何 AI 都会自动检索或遵守；具体使用时仍需明确读取范围和任务要求。

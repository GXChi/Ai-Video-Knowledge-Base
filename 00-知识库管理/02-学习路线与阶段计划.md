## 总体策略

先认识领域全貌，再按兴趣与疑问深入，结合完整案例与必要实践。以知识库 Markdown 阅读为主，聊天用于反馈和答疑，不按术语逐项闯关，也不一次性生成全部课程。

目录是归档结构，路线是建议，不是固定课时。文档写成、用户认可与学习掌握分别记录。

### 后续深入方向

| 方向 | 想解决的问题 | 可形成的成果 |
|---|---|---|
| 人物与关系 | 谁在经历事情，为什么关心他，他为什么行动 | 有用途的人物构思和具体行为 |
| 情节与冲突 | 接下来发生什么，前后怎样推动，为什么让人期待 | 连贯的事件过程、选择与后果 |
| 结构与方法 | 整篇怎样开场、展开、转向与收尾 | 适合当前故事的组织方案 |
| 叙事与表达 | 用什么视角、顺序和详略呈现 | 一篇可独立阅读的故事稿 |
| 修改与反馈 | 哪里不清楚、不可信或不吸引人 | 有明确理由的修订 |

这些方向相互联系，不规定人物、情节、结构必须完全分开学，也不把某套方法当所有故事的标准。

## 从故事向其他领域延伸

故事可以停留为独立文字作品，也可以按兴趣转向小说、剧本、漫画或其他形式。若选择影视表达，后续可学习：

1. 编剧与剧本写作：场景、动作、对白与视听表达。
2. 导演与镜头语言：叙事意图、表演、调度和镜头。
3. 摄影与美术：画面、人物、场景、道具和视觉方向。
4. 分镜与 AI 生成：把设计变成镜头方案和素材。
5. 剪辑与声音：组织最终观看体验。

剪辑和声音的基本作用可以提前了解，工具实践可同步进行。这里不是让用户先完成全部理论再制作，也不是在学习故事时强制进行系列定位或整季规划。

## 每次阅读与修订

1. 确定主题并检查已有内容。
2. 直接写入有完整脉络的 Markdown 草稿，必要时附完整案例。
3. 聊天提供简短入口；用户阅读并以文字或语音反馈。
4. 围绕具体段落解释、对照或局部修订。
5. 按实际需要安排练习，分别记录理解与实践。
6. 当前范围内的必要维护直接完成；是否进入新阶段由用户决定。

文档中出现关联概念可以先简要解释并链接，不因未完成关联课程就禁止阅读。确认学习结果不作为保存草稿的前置条件。

## 进度判断

学习状态可记录未开始、阅读／讨论中、能解释、已实践等，并附实际依据。文档状态使用草稿、待核实、已复核等，不与学习状态混在一起。

不以看完、文件数量或完成了模板作为掌握标准。原先的四周试运行不再作为当前推进依据，以阅读反馈和实际创作为准。
